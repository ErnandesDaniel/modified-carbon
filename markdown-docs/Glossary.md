# Glossary

## Глоссарий

---

# 1. Introduction (Введение)

Данный документ содержит определения терминов, используемых в проектной документации системы управления клиникой Sleeving (SCMS). Глоссарий предназначен для обеспечения единого понимания терминологии всеми участниками проекта: командой разработки, тестировщиками, заказчиком и аудиторами.

## 1.1 Purpose (Назначение)

Назначение документа — предоставить централизованный справочник терминов, аббревиатур и определений, используемых во всех документах проекта SCMS (Vision, SRS, SDP, SAD, TestPlan, RiskList).

## 1.2 Scope (Область применения)

Документ относится к проекту разработки корпоративной информационной системы для элитной клиники переноса сознания в Бей-Сити (2384 год). Используется всеми участниками проекта: разработчиками, тестировщиками, аналитиками, менеджерами и заказчиком.

# 2. Definitions (Определения)

## 2.1 Термины предметной области

### 2.1.1 Cortical Stack (Кортикальный стек)

Устройство размером с монету, имплантируемое в затылок. Хранит сознание на квантовом уровне. Является единственным носителем цифровой личности человека. При физической смерти тела стек может быть извлечён и перенесён в новое тело (sleeve).

### 2.1.2 DHF (Digital Human Freight)

Цифровые данные человеческого сознания, хранящиеся в кортикальном стеке. DHF включает полную квантовую запись личности, воспоминаний и нейронных связей. Передача DHF осуществляется через процедуру needlecast.

### 2.1.3 Needlecast (Нидлкаст)

Процесс беспроводной передачи DHF (цифровых данных сознания) из кортикального стека в нейроны нового тела. Передача осуществляется практически мгновенно. Критическая процедура, требующая 100% целостности данных.

### 2.1.4 Sleeve (Слив)

Клонированное или подобранное тело для переноса сознания. Тело выращивается в генетических архивах или подбирается из каталога по параметрам (рост, вес, генетический профиль). Sleeve является временным носителем для DHF клиента.

### 2.1.5 Sleeving

Процедура переноса сознания клиента из текущего тела в новое (sleeve). Включает этапы: подбор тела, культивирование (при заказе нового), извлечение кортикального стека, needlecast, постпроцедурная валидация (72 часа) и выдача сертификата совместимости.

### 2.1.6 Stack Shock

Психосоматический шок после переноса сознания в новое тело. Проявляется как дезориентация, отторжение тела, фрагментация личности. Требует 72-часового наблюдения и мониторинга со стороны Psychosurgeon.

### 2.1.7 Бей-Сити

Город-мегаполис будущего (2384 год), где происходит действие проекта. Центр индустрии sleeving и хранения кортикальных стеков. Юрисдикция: Протекторат ООН.

### 2.1.8 Протекторат

Международная организация, осуществляющая надзор за технологиями DHF и процедурами sleeving. Устанавливает стандарты безопасности, выдаёт лицензии клиникам, проводит проверки и налагает санкции за нарушения.

### 2.1.9 Генетические архивы

Организации и хранилища, специализирующиеся на культивировании клонированных тел (sleeves). Предоставляют клиникам каталоги доступных тел с параметрами (рост, вес, генетический профиль, возраст, пол). Интегрируются с SCMS через API.

### 2.1.10 Сертификация совместимости

Процедура подтверждения успешности переноса сознания, выполняемая Psychosurgeon по завершении постпроцедурного наблюдения. Результат — сертификат в формате PDF с реквизитами клиники, ID клиента, датами процедур и QR-кодом для проверки подлинности Протекторатом. Сертификат является юридически значимым документом, подтверждающим легальность и успешность процедуры sleeving.

## 2.2 Пользователи системы

### 2.2.1 Meth

Сверхбогатый клиент клиники (от «Мафусаил» — библейский долгожитель). Владелец множества стеков и тел, способный жить сотни лет путём смены sleeves. Бюджет процедуры: 2–50 миллионов кредитов.

### 2.2.2 Sleeve Broker

Специалист, управляющий жизненным циклом sleeves — от заказа тела в генетическом архиве через приёмку и установку в клинике до резервирования за клиентом (Meth). Отвечает за каталог тел, фильтрацию по параметрам, резервирование и подтверждение заказов.

### 2.2.3 Needlecaster

Техник, выполняющий перенос кортикального стека в новое тело (needlecast) и фиксирующий этапы процедуры в системе. Работает в стерильных условиях операционной — основная задача в системе: фиксация результатов каждого этапа, мониторинг статуса передачи DHF и регистрация инцидентов.

### 2.2.4 Psychosurgeon

Врач, проводящий осмотр клиента после переноса (постпроцедурное наблюдение в течение 72 часов), фиксирующий результаты в системе и принимающий решение о выдаче сертификата совместимости. В системе выполняет минимальный объём работ: фиксирует результаты осмотров на контрольных точках (24ч/48ч/72ч) и подтверждает сертификацию.

### 2.2.5 Администратор

Сотрудник клиники, отвечающий за техническую поддержку системы SCMS: управление учётными записями сотрудников, настройка RBAC, мониторинг audit-log, резервное копирование данных, устранение инцидентов безопасности.

### 2.2.6 NDA (Non-Disclosure Agreement)

Соглашение о неразглашении, подписываемое всеми сотрудниками клиники. Обязывает хранить конфиденциальность данных клиентов, результатов процедур и внутренней документации. Нарушение влечёт юридические санкции и увольнение.

## 2.3 Технические термины

### 2.3.1 FR (Functional Requirement)

Функциональное требование — описание конкретной функции, которую система должна выполнять. Формулируется как требование к поведению системы при определённых входных данных. Пример: FR-001-01 — «Система должна обеспечить аутентификацию пользователя».

### 2.3.2 RBAC (Role-Based Access Control)

Ролевая модель доступа — механизм разграничения прав доступа в системе на основе ролей пользователей. Каждая роль (Meth, Sleeve Broker, Needlecaster, Psychosurgeon, Администратор) имеет набор разрешённых операций.

### 2.3.3 SCMS (Sleeving Clinic Management System)

Корпоративная информационная система управления элитной клиникой переноса сознания. Обеспечивает управление каталогами sleeves, процессом needlecast, сертификацией, аудитом и безопасностью данных клиентов.

### 2.3.4 Audit Log (Аудит-лог)

Неизменяемый (append-only) журнал всех операций в системе. Содержит timestamp, ID пользователя, тип операции и параметры. Используется для расследования инцидентов, предоставления регуляторам и юридических запросов.

### 2.3.5 Квантовое шифрование

Метод шифрования данных, использующий квантовые свойства для обеспечения абсолютной безопасности передачи DHF. Применяется для защиты каналов связи между стеками и серверами клиники.

### 2.3.6 2FA (Two-Factor Authentication)

Двухфакторная аутентификация — метод подтверждения личности пользователя с помощью двух независимых факторов: пароля и одноразового кода (SMS/email/app). Обязательна для всех учётных записей сотрудников в SCMS.

### 2.3.7 MTTR (Mean Time To Recovery)

Среднее время восстановления системы после сбоя. Для SCMS: целевое значение MTTR ≤ 4 часа для критических инцидентов (потеря данных, недоступность аудит-лога).

### 2.3.8 Uptime

Показатель доступности системы. Для SCMS: 95% в рабочее время клиники (допустимый downtime ~18 суток/год для планового обслуживания).
