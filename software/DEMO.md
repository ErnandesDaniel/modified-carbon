# DEMO — сценарий демонстрации SCMS

Пошаговый план показа прецедентов UC-01…UC-05 на живом приложении (Vite-порталы + Spring Boot).
Что нажимать, в какой роли и когда переключать роль.

---

## 0. Запуск и адреса

Демонстрация рассчитана на **полностью развёрнутый в Docker стек** (профиль `full`).

```powershell
cd software
Copy-Item infra/.env.example infra/.env
docker compose -f infra/compose.yaml --profile full up -d --build
```

| Компонент | URL | Вход |
| :---- | :---- | :---- |
| Внешний портал (Meth) | http://localhost:3000 | «Войти через Google» или «Демо-вход (M. Kovacs)» |
| Внутренний портал (персонал) | http://localhost:3002 | ввести имя → «Войти как сотрудник» |
| Backend / Swagger | http://localhost:3001/api/swagger-ui/index.html | — |
| pgAdmin | http://localhost:8081 | `admin@admin.com` / `admin` |

Готовность проверить так (backend поднимается последним — он накатывает Liquibase):

```powershell
docker compose -f infra/compose.yaml --profile full ps
# backend готов, когда Swagger отвечает:
Invoke-WebRequest http://localhost:3001/api/v3/api-docs -UseBasicParsing | Select-Object -ExpandProperty StatusCode
```

> Google-вход работает только если redirect URI `http://localhost:3000/api/login/oauth2/code/google`
> добавлен в Google Console. Для демонстрации достаточно **демо-входа**.

> ⚠️ **Перед демонстрацией сбрось базу до исходных сидов** (раздел 9), если она уже
> менялась (например, остались заказы/кейсы от прошлых прогонов). Иначе часть сценариев
> может выглядеть иначе.

## 1. Две сессии — один браузер

Порталы на разных портах, поэтому cookie независимы: держи **две вкладки одновременно**.

- **Вкладка 1** — http://localhost:3000, вход как клиент (демо или Google) → роль `METH`.
- **Вкладка 2** — http://localhost:3002, вход как сотрудник → роль `SLEEVE_BROKER` по умолчанию.

**Роль у пользователя одна.** У персонала она меняется в разделе **«Настройки»** (выбрать
«Роль» → **«Сохранить»**) — меню мгновенно перестраивается под роль.

> Лайфхак: для скорости поставь роль **Администратор** — видны все разделы сразу.
> RBAC покажи отдельно (раздел 4), переключив роль.

### Разделы по ролям

| Роль | Разделы меню |
| :---- | :---- |
| Sleeve Broker | Дашборд, Каталог тел, Заказы, Сертификаты, Настройки |
| Needlecaster | Дашборд, Needlecast, Сертификаты, Настройки |
| Psychosurgeon | Дашборд, Валидация, Сертификаты, Настройки |
| Администратор | все: + Пользователи, Аудит |

## 3. Сквозной сценарий (happy path)

Слева — роль, в которой выполняешь шаг. Роль переключается: **Настройки → Роль → Сохранить**.

### Шаг 1 — UC-05. Клиент входит (вкладка :3000)
1. Открыть http://localhost:3000.
2. Показать **«Войти через Google»** — основной поток прецедента (внешний провайдер).
3. Нажать **«Демо-вход (M. Kovacs)»** — упрощённый вход без Google. Открывается личный кабинет.

*FR: FR-014-01, FR-014-02. Альтернатива AccountExists — раздел 5.*

### Шаг 2 — UC-01. Клиент заказывает тело (вкладка :3000)
1. Меню **«Каталог тел»**. При желании задать фильтры (Пол / Рост / Возраст) → **«Найти»**.
2. У доступного тела нажать **«Заказать»**.
3. Откроется **«Мои заказы»** — новый заказ в статусе **«Новый»**.

*FR: FR-003-01, FR-013-01.*

### Шаг 3 — UC-01. Брокер обрабатывает заказ (вкладка :3002)
1. **Настройки → Роль = Sleeve Broker (или Администратор) → Сохранить.**
2. Меню **«Заказы»**. Найти заказ клиента (статус «Новый»).
3. Нажать **«Подтвердить»** → **«Подтвердить»** в диалоге.
   → Тело закрепляется, создаётся кейс needlecast, заказ → **«Подтверждён»**.
4. (Клиент, вкладка :3000 → **«Кабинет»**) — в таймлайне появился этап, тело зарезервировано.

*FR: FR-013-02.*

### Шаг 4 — UC-03. Needlecast (вкладка :3002)
1. **Настройки → Роль = Needlecaster (или Администратор) → Сохранить.**
2. Меню **«Needlecast»** → открыть кейс в статусе **«Ожидает»** (кнопка «Открыть»).
3. Нажать **«Начать перенос»** → статус **«Перенос в процессе»**, зафиксировано время старта, тело → «Используется».
4. Нажать **«Отметить результат: Успешно»** → статус **«Завершён»**, протокол сохранён.
5. Появится кнопка **«Перейти к валидации»**.

*FR: FR-007-01, FR-008-01.*

### Шаг 5 — UC-04. Осмотр и сертификация (вкладка :3002)
1. **Настройки → Роль = Psychosurgeon (или Администратор) → Сохранить.**
2. Меню **«Валидация»** → открыть кейс после переноса.
3. В чек-листе для каждого пункта выбрать **«Пройден»** (прогресс-бар заполнится).
4. Нажать **«Подтвердить и выдать сертификат»** → появится сертификат `CERT-…` и код проверки.
   → Кейс → **«Завершено»**.

*FR: FR-009-01, FR-010-01/02, FR-011-01/02.*

### Шаг 6 — UC-04/UC-01. Результат у клиента (вкладка :3000)
1. **«Кабинет»** — таймлайн кейса пройден до «Завершено».
2. Меню **«Сертификаты»** → **«Скачать PDF»** (печать/сохранение сертификата).

## 4. RBAC (переключение ролей)

1. Вкладка :3002 → **Настройки** → посмотреть текущую роль.
2. Выбрать **Sleeve Broker** → **Сохранить** → в меню только «Каталог тел» и «Заказы».
3. Выбрать **Needlecaster** → меню «Needlecast».
4. Выбрать **Psychosurgeon** → меню «Валидация».
5. Выбрать **Администратор** → появляются «Пользователи» и «Аудит».

Также: **Пользователи** (`/users`, только Admin) — смена роли другому пользователю.

*FR-015-02.*

## 5. Ветки-исключения

### 5.1 UC-01 ext. NoAvailableSleeves (нет тела)
1. Клиент (вкладка :3000) заказывает тело, которого нет в резерве — например `ORD-1002`
   (или создаёт заказ без доступного тела).
2. Брокер (вкладка :3002, роль Sleeve Broker) → **«Заказы»** → у заказа без тела видна кнопка
   **«Ожидает тело»** → нажать.
   → Заказ → **«Ожидает тело»**; далее брокер пополняет резерв (UC-02, раздел 6).
3. У клиента в **«Кабинете»**/«Мои заказы» статус «Ожидает тело».

### 5.2 UC-03 ext. ProcedureFailed (инцидент)
1. Роль **Needlecaster**, открыть кейс в статусе «Ожидает» → **«Начать перенос»**.
2. Нажать **«Зафиксировать инцидент»** → выбрать тип (Stack Shock / Отторжение / Повреждение
   стека) → описание → **«Зафиксировать»**.
   → Кейс → **«Инцидент»** и заблокирован (готовый пример: `CS-104`).

### 5.3 UC-04 ext. Complications (осложнение)
1. Роль **Psychosurgeon**, открыть кейс на валидации.
2. Нажать **«Зафиксировать осложнение»** → тип (Stack Shock / Фрагментация личности /
   Отторжение) + описание → **«Зафиксировать»**.
   → Кейс → **«Корректирующие процедуры»**, выпуск клиента заблокирован, создан инцидент.

### 5.4 UC-05 ext. AccountExists
1. Вкладка :3000 → выйти (**«Выйти»**) → снова войти тем же способом.
   → Новая учётка не создаётся, выполняется вход в существующий кабинет (дедуп по
   `provider + providerUserId`).

## 6. UC-02 — Пополнение резерва (вкладка :3002)

Роль **Sleeve Broker** (или Администратор) → меню **«Каталог тел»**.

1. Показать таблицу резерва со статусами: «Доступно», «В культивации», «В приёмке»,
   «Зарезервировано», «Используется», «Списано».
2. Кнопка **«+ Заказать культивирование»** → выбрать генетический архив и параметры
   (пол/рост/вес/возраст) → **«Создать заказ»** → новое тело со статусом «В культивации».
3. У тела в статусе «В приёмке» (например `SLV-046`) нажать **«Принять»** → статус «Доступно».
   Кнопка **«Отклонить»** → статус «Списано».
4. У доступного тела **«Зарезервировать»** → выбрать клиента → **«Зарезервировать»**;
   у зарезервированного — **«Снять резерв»**.

*FR: FR-001-01/02/03, FR-002-01/02.*

## 8. Быстрая проверка через API (одной командой)

Полный конвейер без кликов (backend роли не проверяет, поэтому достаточно cookie):

```powershell
$b = "http://localhost:3001/api"
Invoke-RestMethod -Method Post "$b/auth/dev-login"    -ContentType 'application/json' -Body '{"name":"Demo Staff"}' -SessionVariable staff  | Out-Null
Invoke-RestMethod -Method Post "$b/auth/client-dev-login" -SessionVariable client | Out-Null

# UC-01: клиент выбирает тело и оформляет заказ
$sv  = (Invoke-RestMethod "$b/sleeves?availableOnly=true" -WebSession $client)[0]
$ord = Invoke-RestMethod -Method Post "$b/orders" -WebSession $client -ContentType 'application/json' -Body (@{ sleeveId = $sv.id } | ConvertTo-Json)
# UC-01: брокер подтверждает
Invoke-RestMethod -Method Post "$b/orders/$($ord.id)/confirm" -WebSession $staff | Out-Null

# UC-03: needlecast
$case = (Invoke-RestMethod "$b/cases?status=PENDING" -WebSession $staff)[0]
Invoke-RestMethod -Method Post "$b/cases/$($case.id)/start"    -WebSession $staff -ContentType 'application/json' -Body '{"needlecasterName":"Demo Staff"}' | Out-Null
Invoke-RestMethod -Method Post "$b/cases/$($case.id)/complete" -WebSession $staff -ContentType 'application/json' -Body '{"result":"SUCCESS"}' | Out-Null

# UC-04: чекпоинты и сертификат
(Invoke-RestMethod "$b/cases/$($case.id)/checkpoints" -WebSession $staff) | ForEach-Object {
  Invoke-RestMethod -Method Patch "$b/checkpoints/$($_.id)" -WebSession $staff -ContentType 'application/json' -Body '{"status":"PASSED"}' | Out-Null }
$cert = Invoke-RestMethod -Method Post "$b/cases/$($case.id)/confirm" -WebSession $staff
"CERT: $($cert.code) / verification: $($cert.verificationCode)"
```

## 9. Сброс базы до исходных сидов

Данные **сидируются автоматически**: при старте backend Liquibase накатывает
`01-init-schema.sql` (схема) и `02-seed-data.sql` (данные). Дополнительно ничего готовить
не нужно.

> ❗ `docker compose down` **без** флага `-v` данные **сохраняет** — сиды повторно не
> применятся. Сбрасывает именно `-v`: он удаляет volume `scms_pgdata`, после чего при
> следующем старте backend накатывает схему и сиды заново.

### Полный стек в Docker

```powershell
cd software
docker compose -f infra/compose.yaml --profile full down -v      # остановить + удалить данные БД
docker compose -f infra/compose.yaml --profile full up -d --build
```

> Демонстрация идёт на профиле `full`; отдельный dev-режим (infra + `mvn`) здесь не нужен.

### Что будет в свежей БД

| Сущность | Значения |
| :---- | :---- |
| Клиенты | `M. Kovacs` (демо-вход) и другие |
| Заказы | `ORD-1001`, `ORD-1002` («Ожидает тело»), `ORD-1003` |
| Кейсы | `CS-101` (завершён + `CERT-CS-101`), `CS-102` (в процессе), `CS-103` (ожидает), `CS-104` (инцидент) |
| Тела | 10 шт., в т.ч. `SLV-046` (в приёмке) и доступные для заказа |
| Стек клиента | `STK-77` у M. Kovacs (нужен, чтобы при подтверждении заказа создался кейс) |

### Проверка, что сиды на месте

```powershell
$b = "http://localhost:3001/api"
Invoke-RestMethod -Method Post "$b/auth/dev-login" -ContentType 'application/json' -Body '{"name":"Demo Staff"}' -SessionVariable s | Out-Null
"кейсов: $((Invoke-RestMethod "$b/cases" -WebSession $s).Count); сертификатов: $((Invoke-RestMethod "$b/certificates" -WebSession $s).Count)"
```

## 10. Чек-лист преподавателя

- [ ] **UC-05** — вход клиента, создан личный кабинет (+ AccountExists при повторном входе).
- [ ] **UC-01** — клиент оформил заказ, брокер подтвердил, тело зарезервировано.

- [ ] **UC-03 ext** — инцидент зафиксирован, кейс заблокирован.
- [ ] **UC-04** — чекпоинты пройдены, сертификат сгенерирован.
- [ ] **UC-04 ext** — осложнение зафиксировано, выпуск заблокирован.
- [ ] **RBAC** — смена роли в «Настройках» меняет меню; «Пользователи» — назначение роли.
- [ ] **Аудит** — все действия отражены в журнале.
