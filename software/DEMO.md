# DEMO — план демонстрации SCMS

Документ для показа преподавателю: как за 10–15 минут доказать, что реализованное ПО
покрывает прецеденты **UC-01…UC-05** из [`markdown-docs/Usecase.md`](../markdown-docs/Usecase.md)
и соответствует требованиям SRS/FR.

---

## 0. Что понадобится

| Компонент | Порт | URL |
| :---- | :---- | :---- |
| Backend + API + Swagger | 3001 | http://localhost:3001/api/swagger-ui/index.html |
| Внешний портал Meth | 3000 | http://localhost:3000 |
| Внутренний портал персонала | 3002 | http://localhost:3002 |

### Запуск (3 терминала + Docker)

```powershell
# Терминал 1 — БД + backend
cd software/backend
docker compose up -d
mvn spring-boot:run

# Терминал 2 — внутренний портал
cd software/internal-portal
pnpm install; pnpm dev

# Терминал 3 — внешний портал
cd software/client-portal
pnpm install; pnpm dev
```

### Учётные записи

- **Сотрудник (внутренний портал):** кнопка «Войти как сотрудник» (дефолтный `Demo Staff`).
  Роль меняется в разделе **Настройки** — это ключевая фишка RBAC.
- **Клиент (внешний портал):** «Демо-вход (M. Kovacs)» или Google OAuth.

### Роли персонала (переключаются в «Настройках»)

| Роль в настройках | Что открывается в меню |
| :---- | :---- |
| Sleeve Broker | Каталог тел, Заказы |
| Needlecaster | Needlecast |
| Psychosurgeon | Валидация |
| Администратор | Все разделы + Пользователи, Аудит |

> Начать демонстрацию удобно с роли **Администратор** — видны все разделы сразу.

## 1. Соответствие прецедентов и экранов

| UC | Название | Где показываем | Главные действия |
| :---- | :---- | :---- | :---- |

## 2. UC-05 — Регистрация клиента (RegisterMeth)

**Открыть:** http://localhost:3000/login

1. Показать кнопку **«Войти через Google»** — это основной поток прецедента (внешний провайдер).
2. Нажать **«Демо-вход (M. Kovacs)»** — упрощённый вход для демонстрации без Google.
3. Система создаёт/находит учётную запись Meth и открывает личный кабинет `/cabinet`.

**Что подчеркнуть:**
- Вызов backend `POST /auth/login` (для Google) и `POST /auth/client-dev-login` (демо).
- Создание учётной записи и личного кабинета — FR-014-01, FR-014-02.
- Альтернативный поток **AccountExists**: повторный вход не создаёт дубликат (identity ищется по provider+providerUserId).

## 3. UC-01 — Заказ тела клиентом (OrderSleeve)

### 3.1. Клиент оформляет заказ
1. Войти на http://localhost:3000 (демо-вход M. Kovacs).
2. Меню **«Каталог тел»** → применить фильтры (пол / рост / возраст) → **«Найти»**.
3. У доступного тела (например `SLV-047`, `SLV-051`, `SLV-088`, `SLV-095`) нажать **«Заказать»**.
4. Перейти в **«Мои заказы»** — новый заказ со статусом **«Новый»**.

### 3.2. Sleeve Broker обрабатывает заказ
1. Войти на http://localhost:3002 как сотрудник, роль **Sleeve Broker** или **Администратор**.
2. Раздел **«Заказы»** — виден заказ клиента.
3. Нажать **«Подтвердить»** → тело резервируется за клиентом, создаётся кейс needlecast.

### 3.3. Точка расширения NoAvailableSleeves
- Заказ **`ORD-1002`** (Рэйчел Ковачски) уже в статусе **«Ожидает тело»** — показать, что при
  отсутствии тела в резерве брокер заказывает культивирование (см. UC-02), а заказ ждёт поступления.
- Кнопка **«Ожидает тело»** доступна у заказов без выбранного тела.

**Эндпоинты:** `POST /orders`, `GET /orders/mine`, `GET /orders`, `POST /orders/{id}/confirm`,
`POST /orders/{id}/await-body`. **FR:** FR-003-01, FR-013-01, FR-013-02.

## 4. UC-02 — Пополнение резерва тел (ManageSleeveReserve)

**Открыть:** internal-portal → **«Каталог тел»** (`/sleeves`)

1. Показать текущий резерв и статусы: `AVAILABLE`, `CULTIVATING`, `INTAKE`, `RESERVED`, `IN_USE`.
2. Нажать **«Культивирование»** → заполнить форму (архив, пол, рост/вес/возраст) → **«Создать заказ»**.
   - Новое тело появляется со статусом **«В культивации»** и процентом готовности.
3. Приёмка: у тела `SLV-046` (статус **«В приёмке»**) нажать **«Принять»** → статус меняется на **«Доступно»**.
   (Кнопка **«Отклонить»** → статус «Списано» — показать при желании.)
4. Резервирование: у доступного тела нажать **«Зарезервировать»** → выбрать клиента → тело закреплено.

**Эндпоинты:** `GET /sleeves`, `GET /sleeves/archives`, `POST /sleeves/cultivation`,
`POST /sleeves/{id}/intake/accept|reject`, `POST /sleeves/{id}/reserve`.
**FR:** FR-001-01/02/03, FR-002-01/02.

---

## 5. UC-03 — Проведение needlecast (ConductNeedlecast)

**Открыть:** internal-portal → **«Needlecast»** (`/needlecast`)

1. В списке есть кейсы в разных статусах. Выбрать `CS-103` (статус **«Ожидает»**) → **«Открыть»**.
2. Показать карточку процедуры: клиент, стек, тело.
3. Нажать **«Начать перенос»** → статус **«Перенос в процессе»**, фиксируется время старта, тело → «Используется».
4. Нажать **«Отметить результат: Успешно»** → статус **«Завершён»**, сохраняется протокол.

### Точка расширения ProcedureFailed
1. Взять другой кейс в статусе «Ожидает» → **«Начать перенос»**.
2. Нажать **«Зафиксировать инцидент»** → выбрать тип (Stack Shock / Отторжение / Повреждение стека),
   указать описание → кейс переходит в **«Инцидент»** и блокируется.
   - Готовый пример: `CS-104` (Лоренс Банкрофт) — Stack Shock.

**Эндпоинты:** `GET /cases`, `POST /cases/{id}/start|complete|incident`, `GET /cases/{id}/incidents`.
**FR:** FR-007-01, FR-008-01, FR-008-02.

## 6. UC-04 — Осмотр и сертификация (ExamineAndCertify)

**Открыть:** internal-portal → **«Валидация»** (`/validation`)

1. Выбрать кейс после needlecast (например `CS-102`, статус «Перенос в процессе», или любой завершённый).
2. Пройти **чек-лист осмотра**: для каждого пункта выбрать **«Пройден»** / **«Провал»**.
3. Когда все обязательные пройдены — нажать **«Подтвердить и выдать сертификат»**.
   - Система генерирует PDF-сертификат с **кодом проверки (QR)**, кейс → **«Завершён»**.
4. Показать выданный сертификат в разделе **«Сертификаты»**, а у клиента — в `/cabinet/certificates`.

### Точка расширения Complications
1. На странице осмотра нажать **«Зафиксировать осложнение»** → тип (Stack Shock / Фрагментация
   личности / Отторжение) + описание.
2. Кейс переходит в **«Корректирующие процедуры»**, выпуск клиента заблокирован, создан инцидент.

> `CS-101` (M. Kovacs) уже завершён и имеет сертификат **`CERT-CS-101`** — удобно показать результат,
> не выполняя шаги заново.

**Эндпоинты:** `GET /cases/{id}/checkpoints`, `PATCH /checkpoints/{id}`,
`POST /cases/{id}/confirm`, `POST /cases/{id}/complications`, `GET /certificates`.
**FR:** FR-009-01, FR-010-01/02, FR-011-01/02.

## 7. Дополнительно (архитектурные требования SRS)

| Требование | Где показать |
| :---- | :---- |
| Два раздельных портала, единый API (SRS 3.6.1) | client-portal :3000 и internal-portal :3002 работают с одним backend :3001 |
| Ролевая модель RBAC (FR-015-02) | «Настройки» — смена роли меняет меню; «Пользователи» — назначение ролей |
| Аудит операций (FR-012-01, FR-022-01) | internal-portal → **«Аудит»**: вход, резерв, needlecast, сертификация |
| Дашборд клиники (FR-016-01) | internal-portal → **«Дашборд»** (счётчики тел, кейсов, инцидентов) |
| Дашборд Meth / таймлайн (FR-016-02) | client-portal → `/cabinet` (шаги кейса) |
| Изоляция данных Meth (FR-013-02) | `/cabinet` и `/orders/mine` показывают только данные текущего клиента |

## 9. Прямая проверка API (если спросят «а backend работает?»)

Открыть Swagger: http://localhost:3001/api/swagger-ui/index.html

Быстрый сценарий через PowerShell:

```powershell
$base = "http://localhost:3001/api"
$auth = Invoke-RestMethod -Method Post -Uri "$base/auth/dev-login" `
        -ContentType "application/json" -Body '{"name":"Demo Staff"}'
$h = @{ Authorization = "Bearer $($auth.token)" }

# UC-02: заказать культивирование
Invoke-RestMethod -Method Post -Uri "$base/sleeves/cultivation" -Headers $h `
  -ContentType "application/json" `
  -Body '{"gender":"FEMALE","height":174,"weight":60,"age":27,"geneticArchiveId":3}'

# UC-01: подтвердить заказ ORD-1003
Invoke-RestMethod -Method Post -Uri "$base/orders/3/confirm" -Headers $h

# UC-03: старт и завершение переноса
Invoke-RestMethod -Method Post -Uri "$base/cases/2/start" -Headers $h `
  -ContentType "application/json" -Body '{"needlecasterName":"Demo Staff"}'
Invoke-RestMethod -Method Post -Uri "$base/cases/2/complete" -Headers $h `
  -ContentType "application/json" -Body '{"result":"SUCCESS"}'

# UC-04: пройти чекпоинты и выдать сертификат
(Invoke-RestMethod -Uri "$base/cases/2/checkpoints" -Headers $h) |
  ForEach-Object { Invoke-RestMethod -Method Patch -Uri "$base/checkpoints/$($_.id)" `
    -Headers $h -ContentType "application/json" -Body '{"status":"PASSED"}' | Out-Null }
Invoke-RestMethod -Method Post -Uri "$base/cases/2/confirm" -Headers $h
```

Каждый вызов возвращает результат, соответствующий шагу прецедента (заказ, резерв, кейс, сертификат).
