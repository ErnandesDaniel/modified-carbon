# **1\. Introduction (Введение)**

## **1.1 Purpose (Назначение)**

Настоящий документ содержит определения ключевых терминов и аббревиатур, используемых в проекте «Classroom of the Elite». Глоссарий обеспечивает единое понимание терминологии командой разработки, стейкхолдерами и пользователями системы.

## **1.2 Scope (Область применения)**

Глоссарий охватывает термины из документов: Vision, SRS, SDP, SAD, Use Case Specification, Risk List, Test Plan.

# **2\. Definitions (Определения)**

## **2.1 Доменные термины (предметная область)**

| Термин | Определение | Источник |
| :---- | :---- | :---- |
| S-очки (S-Points) | Внутренняя балльная валюта системы. Начисляются по итогам экзаменов, списываются за нарушения или при использовании привилегий. | Vision, SRS |
| Ранг класса (A/B/C/D) | Категория класса, присваиваемая администрацией по итогам семестра. A \- наивысший, D \- наименьший. | Vision, SRS |
| Тайное голосование (Secret Voting) | Анонимная процедура голосования по вопросам исключения участника. Анонимность: связь voter\_id \<-\> vote разрывается криптографически. | Vision, SRS, Use Case |
| Сговор (Collusion) | Нарушение правил экзамена путём координации ответов. Фиксируется экзаменатором и сохраняется в журнале нарушений. | Vision, SRS, Use Case |
| Привилегия класса | Особое право/ресурс, доступный классу при наличии достаточного баланса S-очков. Куратор подаёт заявку; система проверяет баланс автоматически. | Vision, SRS |
| Сводная панель прогресса (Dashboard) | Страница с балансом S-очков всех классов, рангами и динамикой в реальном времени. | Vision, SRS |
| Прокторинг (Proctoring) | Технический контроль студента во время экзамена: запрет переключения вкладок, захват веб\-камеры, фиксация потери фокуса. | SRS, Use Case |
| Фокус-лок (Focus Lock) | Браузер переходит в fullscreen-режим; переключение на другое приложение фиксируется как нарушение. | SRS |

## **2.2 Роли пользователей**

| Роль | Описание | Основные операции |
| :---- | :---- | :---- |
| Администрация школы | Управляющий персонал, полные права доступа. Инициатор проекта. | Добавление/удаление учеников, обновление рангов, финансирование. |
| Куратор класса | Педагог, ответственный за отдельный класс. | Фиксация нарушений, управление ресурсами класса, заявки на привилегии. |
| Студент класса | Учащийся \- основной пользователь экзаменационного интерфейса. | Участие в экзаменах, в голосованиях, просмотр результатов. |
| Экзаменатор-модератор | Управляет полным циклом экзамена от создания до финализации. | Создание экзаменов, мониторинг, фиксация сговоров, управление статусами. |

## **2.3 Методологические термины**

| Аббревиатура | Расшифровка | Определение |
| :---- | :---- | :---- |
| RUP | Rational Unified Process | Итерационная методология: Inception, Elaboration, Construction, Transition. |
| SRS | Software Requirements Specification | Документ требований. Функциональные и нефункциональные требования к системе. |
| SDP | Software Development Plan | Документ плана разработки (данный документ). |
| SAD | Software Architecture Document | Документ архитектуры: компоненты, диаграммы развёртывания, ключевые решения. |
| Vision | \- | Документ концепции: бизнес-возможности, стейкхолдеры, функции, бюджет. |
| Risk List | \- | Реестр рисков с вероятностью, влиянием, индикаторами, стратегиями смягчения. |
| Use Case Specification | \- | Сценарии взаимодействия пользователей с системой. |
| CR | Change Request | Запрос на изменение требований после заморозки (конец Elaboration). |
| MTTR | Mean Time To Repair | Среднее время восстановления системы после сбоя. |
